# Cross-cutting notes (hand-written page)

Notes that cannot be generated from tables, in one place.

Generated pages: [api.md](api.md) (identifiers), [kinds.md](kinds.md) (program kinds and capabilities), [ops.md](ops.md) (emitted ops), [codes.md](codes.md) (reason codes and fixes), [examples.md](examples.md) (examples).

## Differences from Go semantics (rules that are not silenced)

- **Integers**: fixed-width integer arithmetic wraps on overflow, as in Go (checked against Go by differential tests). **A divisor must be a non-zero constant** (a variable divisor is GB012); signed `/ -1` is rejected (MinInt / −1). A general signed constant divisor is expanded by the frontend into a division of magnitudes plus a sign correction. A shift count must be a constant within the width
- **Map key range**: an Update / AtomicAdd on an Array with a variable key ≥ MaxEntries **silently does nothing** (the kernel's −E2BIG is not returned). A key the frontend cannot prove in range is the Conditional GB020 — prove it with a clamp or a mask
- **nil**: the result of Lookup can be used only inside the `p != nil` arm (GB005). There is no implicit zero
- **packet**: the API has no read that returns 0 out of range — reads are only through the window inside the `ok` arm of `ctx.Check`
- **ring buffer**: `Output` drops the event when the reservation fails — count it with the return value or `CountDropsIn` (a statement that discards it is GB017)

## Reproducible generated files

- The same Go source gives the same `.mlir`, schema and ELF (byte-identical — the gate regenerates and compares). The provenance of the generated files records the ebpf-compile version and sha256 and the bpf-mlir version (an ebpf-compile of a different version stops before generation)
- Byte-identical in a fresh clone too (measured on 31 packages, 93 files)

## Non-root loaders

- The acceptance table per capability set is [docs/nonroot.md](../nonroot.md) (kernels 7.1.8, 6.12.111 and 6.6.157 × 6 capability sets). Roughly: XDP / tcx programs need **CAP_BPF + CAP_NET_ADMIN**, fentry / fexit need **CAP_BPF + CAP_PERFMON**, and a **variable packet offset** (after the IHL, a walk inside a loop) needs **+ CAP_PERFMON**
- A variable index into a record array (ref.index) is rejected for non-root loaders on 6.x kernels when a constant default value can reach the index — the ebpf-compile warning GB024 names the position. The mask-and-recheck lowering of the checked index does not make this form accepted
- **A form that the mask-and-recheck lowering made accepted**: using the same index into the record arrays of lookups in two maps — an ELF without that lowering is rejected on 6.12 / 6.6 with {CAP_BPF, CAP_NET_ADMIN}, and the ELF with it is accepted on all three kernels with all three capability sets. An array at the end of a record whose element count is not a power of two is outside that lowering's guarantee, and the GB024 warning is emitted

## Kernel 6.6 and the walk unroll count

- For a packet walk inside a loop, the verifier's processed count on 6.6.157 grows sharply with the unroll count N (9190 at N = 8, 69177 at 16, 561836 at 28). If you target 6.6, keep N ≤ 16 as a guide (examples/tcpopts uses 16 and is accepted on all three kernels). The table is in [docs/nonroot.md](../nonroot.md)

## Direction of fexit signature errors

- A directive `nargs` that is too large is also rejected by the verifier. **Too small a count, or a wrong return width or sign, passes the verifier and the value is silently wrong** — only the checked `gobpf.Load` (the retsig check) guards it. `LoadUnchecked` skips this check

## Conditional diagnostics (generation does not stop)

- **GB020**: a variable Array key that cannot be proven in range (out of range silently does nothing)
- **GB024**: an ebpf-compile warning copied with the Go position and the note positions (the text is not matched: a warning with unknown text also becomes GB024). There are two warnings today: (1) a form where a constant and an unknown value reach a ref.index index from different paths (fix: use the index inside the checked arm of the Lookup), and (2) **a ref.index into an array at the end of a record whose element count is not a power of two** — the mask range of the checked index reaches outside the record, so non-root acceptance depends on register allocation (fix: add `_ [N]byte` after the array up to the next power of two). Output of a form ebpf-compile does not know (a line that is not a warning or a note) stops generation
- Both stay in the go generate output and in the conditional section of the generated file

## Tail calls

- Declare a slot with `var _ = bpf.TailSlot(&M, slot, Prog)`; `gobpf.Load` checks it and then sets only the declared slots. TailCall is a single top-level statement in an xdp body, and the statements after it are the fallback
- The chain limit is 33 (all three kernels). A form that gives 17 on 6.6 (a chain with attempts on empty slots in between) cannot be written in the subset

## Packet rewriting

- `ctx.AdjustHead` / `AdjustTail` invalidate the window whether they succeed or fail — a later use stops at the Go line (GB025). Re-read with `ctx.Check`. A failure is −22 and leaves the packet unchanged. AdjustTail only shrinks

## Loop unroll estimate

- A bounded loop without a directive is unrolled, and the estimate N × (body + 4) ≤ 4096 is counted the same way as bpf-mlir (they agree at the boundary). Above it, GB018 names the body estimate and N (for a large body, use `//gobpf:loop backedge` from the next section)

## Loop modes (`//gobpf:loop backedge` / `//gobpf:loop callback`)

- `//gobpf:loop backedge` on the line before a for gives a **(B) bounded back-edge** loop (bpf-mlir's `ebpf.loop N` — without the unroll word). It is not unrolled, so there is no 4096 estimate limit — **N ≤ 64, and the nesting rules are the same as (U)** (bpf-mlir's limits for all modes). Without a directive it is (U) unrolled as before; there is no automatic fallback
- **The body of (B) cannot use ctx.Check or a packet window** (GB018 — bpf-mlir accepts packet.check only in a (U) body). Use a (U) loop to walk a packet
- **On 6.12 / 6.6, a loader without CAP_PERFMON has a (B) loop rejected at load** (adding CAP_PERFMON makes it accepted; the C equivalent behaves the same). **On 7.1.8, a loader without CAP_PERFMON depends on the form**: a loop with a constant count and no branch on an unknown value in the body is accepted, and a loop with an unknown bound and break (64 iterations) is rejected with `The sequence of 8193 jumps is too complex.` — the verifier without CAP_PERFMON stacks a speculative path for each branch whose direction it knows (sanitize_speculative_path in 7.1.8's verifier.c, limit BPF_COMPLEXITY_LIMIT_JMP_SEQ 8192 — which sequence of paths reaches the limit is not confirmed). To target 6.12 / 6.6 with a loader without CAP_PERFMON, use a (U) loop. Using a loop's IV as a record-array index is rejected for loaders without CAP_PERFMON on all three kernels
- `//gobpf:loop callback` on the line before a for gives an **(H) bpf_loop callback** loop (bpf-mlir's `ebpf.loop N callback` — the body becomes a static callback function, positioned at the call of the helper `loop`). It is not unrolled, so there is no estimate limit — N ≤ 64, the nesting rules, bound, break / continue and integers carried across the loop are the same as (U) / (B)
- **The body of (H) cannot use the context** (GB018 — ctx methods, passing ctx to a subprogram; bpf-mlir lets only integers and map handles into the callback). Read the packet before the loop and use integers. Packet windows and checked pointers cannot be used in a loop of any mode
- The bpf_loop helper is usable with CAP_BPF on all three kernels (after the CAP_BPF gate and before the CAP_PERFMON gate of bpf_base_func_proto). **A loader without CAP_PERFMON (CAP_BPF + CAP_NET_ADMIN) had (H) loops accepted on all three kernels** (both a constant 64-iteration body and the bound-and-break body that (B) had rejected on 7.1.8). For loops shipped to loaders without CAP_PERFMON, use (U) or (H)

## Subprogram borrowed arguments and global subprograms

- A subprogram can take one pointer `*T` to a map value (an integer or a record) — reads and **writes to record fields** (`p.F = v`, `p.F++`, `p.F += d`, `bpf.AtomicAdd(&p.F, d)`). `*p = v` on an integer value does not exist, as in a program (for an integer map, use `M.Update` / `M.AtomicAdd`)
  - **A non-atomic RMW of a shared map value stops at the call site** (a callee summary — the rule of the "Non-atomic read-modify-write of shared maps" section across a function boundary): a callee's `p.N++` / `p.N += d` / `p.N = …p.N…` (also through a local variable) gives GB028 on a call that passes a shared (not per-CPU) map value to that callee (naming the position inside the callee — a call that passes a per-CPU map value is accepted). A callee writing an argument value to `p.N` while the caller builds that argument from the same value (`set(p, p.N+1)`) is also GB028, and a callee's `bpf.AtomicAdd(&p.N, d)` whose d the caller passes from the same record (`addN(p, p.M)`) is GB021. `bpf.AtomicAdd(&p.N, p.M)` inside the callee and the form through a local are GB021, as in a program
  - On real kernels: field stores (64 / 32 bit), `bpf.AtomicAdd`, per-CPU `++` / `+=`, stores in a maybe_ref arm, and stores in helpers taking a window and a borrow agree with the Go model on all three kernels as root; running a callee's `bpf.AtomicAdd` in parallel on per-CPU threads loses no counts; the non-root table has the row `cwrite`
  - Passing a checked borrow: `if p := M.Lookup(k); p != nil { v = total(p) }` — the callee reads without a check
  - Passing an unchecked Lookup directly: `v = orZero(M.Lookup(k))` — the callee reads only inside the `if p != nil { … }` arm (outside is GB005)
  - Every call site of the same callee must use the same form (if mixed, GB013 names every site). Passing a borrowed argument on to another subprogram, or a second borrowed argument, is GB013
- **`//gobpf:global`** just before a subprogram makes it global (the verifier verifies the callee once, from the argument types only). The default is static (verified in the caller's context)
  - **A global with a checked borrowed argument (arg:nonnull) cannot be loaded on 6.6.157** — gobpf.Load stops before load with the gate's arg_tag (that kernel does not read arg:nonnull). Integer-only globals and globals with an unchecked borrow (maybe_ref) pass on 6.6 too. Use static if you target 6.6
  - Cost: a call inside a loop in a global is also proportional to the number of calls — the slope is about half of static (215 vs 467 at 64 iterations). Only the verification of the callee body happens once
  - Range: a global does not carry the caller's value ranges in, but a gobpf callee can only be written in forms that show the index range inside itself (GB006), so making it global does not change acceptance
- The context, packet windows, ring buffer reservations and timer / lock records cannot be arguments (not in bpf-mlir's subprogram contract — outside the scope)

## Subprogram packet-window arguments

- `func keyOf(w bpf.Window) uint32 { … w.BE16(12) … }` called as `if w, ok := ctx.Check(off, n); ok { k = keyOf(w) }` in the caller — a `!ebpf.pkt_window<N>` argument of a static `ebpf.func` in bpf-mlir (the kernel passes the packet pointer and range to a static callee as they are). **`bpf.Window` is the same type for XDP and tcx Check** — one helper can be called from XDP and from tcx ingress / egress programs (keyLong / keyShort in examples/tccount)
- **The length N must be the same n in Check at every call site** (otherwise GB013 — the length is part of the window type, and bpf-mlir does not pass a long window as a short one either). Reads and writes inside the callee follow the same rules as in the caller (constant index, `i + width <= N` — GB014)
- **A helper has no ctx** — it cannot call Check or AdjustHead. For nested Checks (two windows of different lengths), check the longer first in the caller (`if w, ok := ctx.Check(0, 24); ok { … } else { if w2, ok2 := ctx.Check(0, 14); ok2 { … } }` — an else-if after ctx.Check cannot be written). Passing a stale window after an adjust is GB025
- **Writes** (`w.SetBE16` etc.): only when every program that calls the helper is xdp (a writing helper called from a tcx program is GB013 — bpf-mlir also names it at compile)
- **Static only, one window** (a window in a `//gobpf:global` is GB013). Forwarding a received window to another helper is stopped by go with GB013 (bpf-mlir accepts it — to be relaxed if there is demand)
- **One window and one map value pointer in the same helper**: `func f(w bpf.Window, p *T) …` is accepted. The borrow follows the borrowed-argument rules (including writes — an RMW of a shared map is GB028 at the call site, and the caller passes a checked p or `M.Lookup(k)` directly), and the window follows the rules above (length; writes only for xdp). At the call, the window must be inside the in_range of `ctx.Check` and the borrow inside the checked arm — in either nesting order. Since the helper's return value carries the borrowed field, `p.F = f(w, p)` (shared map) is GB028 (writing to a borrow of a different map is accepted)
- Cost: a static helper is verified at each call. Turning tccount into the helper form adds +24 to 30% verified instructions on the three kernels (220 → 273, 218 to 221 → 283 — paths increase with integer helper calls inside the helper and with the longest-first Check), in exchange for less body duplication. **How to choose: a helper that removes duplication does not lower the verifier cost** (a static helper is verified at each call, and paths may increase — the same as scope G24 and G31). Use helpers for readability and a single place to fix — to lower cost, keep bodies small, and for programs near the verifier's instruction limit, measure against the inline form
- Execution range: test run does not accept frames shorter than 14 bytes, and a tcx skb test run needs 34 bytes for IPv4 and 54 for IPv6 (the kernel's bpf_prog_test_run_skb) — check the classification of short frames with a real veth attach on the host

## Subprogram context arguments

- A static helper can take **the concrete type of a program context as its first argument** — `func key(ctx *bpf.XDPContext) uint32`, `*bpf.TCIngressContext`, `*bpf.TCEgressContext`, `*bpf.FentryContext`, `*bpf.KprobeContext`, `*bpf.UprobeContext`. The caller passes its own context variable as is (the program's ctx, or forwarding the ctx of a helper that received a context)
- Inside the helper the context can be used for `ctx.Check` and window reads (window writes too in an xdp helper), stack ids (`KernelID` / `UserID`), perf `Output` (fentry), and forwarding to another helper. **Attach-dependent reads (KprobeArg, UprobeArg / UprobeStr, FentryArg, TPArg) and AdjustHead / AdjustTail are GB013** — read them in the caller's program and pass integer arguments (bpf-mlir also rejects them in a callee — both stop it). Tail call, redirect, WithLock / timer are only in the program body (today's GB023 / GB005 / GB026)
- **One helper takes one context type** (bpf-mlir's one func, one kind; the Go types differ too) — to write the same parse for xdp and tc, use a helper that takes a window (the section above). The context is only the first argument (bpf-mlir rejects a context after a map handle — the frontend fixes it to Go's first argument), a global helper cannot take a context (GB013), and `*bpf.FexitContext[R]` and `*bpf.TPBTFContext` cannot be passed (the only ops usable on those contexts are attach-dependent reads)
- On real kernels: helpers for xdp (Check and window reads, forwarding, window writes), tcx ingress and fentry (stack ids, and perf Output including forwarding to that helper) agree with the Go model on all three kernels as root; the non-root table has the row `ctxarg`. Helpers taking kprobe, uprobe and tcx egress contexts are measured only up to generation and ebpf-compile. See the tutorial for usage

## Calls inside loops

- A loop body can call a subprogram (a static function). The callee stays a BPF bpf-to-bpf call (one call per unrolled copy — the callee body is not counted in the unroll estimate). It agrees with the inline form and the Go model on all three kernels (pure computation, a loop in the callee, a call after break / continue, branching on the return value)
- **Path rules** (GB018 — the same as bpf-mlir's call-graph check; the verdicts agree on 11 boundary cases): (R1) the callees (transitively) of a call inside a loop cannot reach the ring buffer (`Output` / `OutputStr`) — put the ring buffer after the loop; (R2) the loops on a path from the program entry, **counting the caller's loops too**, must have nesting depth ≤ 2 and a product of counts ≤ 64. The message names the path (`Prog → loop 4 → deep → loop 8 → loop 8`)
- A callee can receive integers and bool, a borrowed map value ("Subprogram borrowed arguments and global subprograms"), a packet window ("Subprogram packet-window arguments") and the program context ("Subprogram context arguments" — a call inside a loop is measured only up to generation and ebpf-compile) — timers and spin locks cannot be used inside a subprogram (GB026)
- **Moving a body into a function does not necessarily lower the verifier cost**: the callee / inline ratio of verified instructions is 0.79 to 3.0 depending on the form and kernel (LLVM folds the inline form but not the call). It only helps to avoid the (U) estimate of 4096 (64 iterations of a large body that would be GB018 inline). Not recommended — stated as a fact for when you hit the estimate
- bpf_loop callbacks of this kind (the second half of bpf-mlir's F09) are outside the scope

## Global variables (`bpf.Config` — .rodata, `bpf.Global` — .bss)

- **Config** is a setting that user space `Set`s **before** load. **Loading without Setting a non-Optional Config makes Load and LoadUnchecked stop, naming the Config** (it does not silently run with 0). If 0 is intended, use `Set(0)` or `bpf.Config[T]{Optional: true}`. `Set` after load is an error (the kernel freezes .rodata)
- On the eBPF side, **Global**'s `Load()` is one volatile read (not acquire) — ordering against a concurrent `Add` is not guaranteed. A user-side `Get` while running is also approximate. **There is no user-side Set on Global** — so a running write never races with an atomic `Add` on the eBPF side
- **`G.Add(d)` where d carries a `G.Load()` of the same global is GB021**: `G.Add(G.Load() & 0xFF)`, through a local `v := G.Load() & 0xFF; G.Add(v)`, across a helper `bump(G.Load() & 0xFF)` (bump does `G.Add(d)`), `G.Add(get())` (get returns `G.Load()`) — the read and the add are not one atomic, and an add from another CPU in between gives a wrong value (the same kind as GB021 for a map AtomicAdd delta). The delta can come from a constant, the packet, another global / map value or a Config
- Several globals can be placed in the same section (.rodata / .bss) (bpf-mlir's go/layout.CheckGlobals applies .rel.BTF and checks them)

## lpm_trie (`bpf.LPMTrie4`)

- The key is the record `gobpf_lpm_key4` {prefixlen: u32, addr: u8[4]} held on the bpf side (bpf-mlir's IPv4 key convention), and the flags are BPF_F_NO_PREALLOC. IPv6 is out of scope
- The eBPF side is **read-only**: `v, ok := M.Lookup([4]byte{a, b, c, d})` — a longest match on the address (prefixlen 32), with the address bytes in network order (the packet's byte order as is). It returns by value, so writing through a borrow or AtomicAdd cannot be formed by the types. The value is read with **a single ref.load** inside the present arm (it does not mix with a concurrent Put from user space)
- Packet bytes can only be read from a `ctx.Check` window, so the form of looking up with the 0 of an out-of-range packet.load cannot be written
- User space: `Put` / `Remove` take a `netip.Prefix` — a non-IPv4, invalid or **host-bits-set prefix is an error** (no silent `Masked()`). A Put of a new prefix into a full table is ENOSPC; a Put of an existing prefix (overwrite) succeeds even when full. `Match` is the kernel's longest match (syscall LOOKUP — not an exact match); for exact entries use `Iterate`

## kprobe (`//gobpf:kprobe` and `bpf.KprobeArg`)

- `//gobpf:kprobe <kernel function>` with `func f(ctx *bpf.KprobeContext)` — x86_64 only. The function name is the kernel function itself (the frontend stops a `__x64_` prefix)
- Arguments are `bpf.KprobeArg[T](ctx, n)` — n is a constant 1 to 6, T is an 8 to 64-bit integer and becomes the schema params (reading the same n with two types is GB008). The value is the low T-width of the register (reading a 32-bit argument as int32 / uint32 does not use the undefined upper 32 bits)
- **A mismatch between T and the kernel argument type (width, sign) is stopped by gobpf.Load before load** (the target BTF and the kprobearg check)
- **The value (address) of a pointer argument**: the in-place conversion `uint64(bpf.KprobeArg[uintptr](ctx, n))` (ptr in the schema params).
- **Reading through a pointer argument** (bpf-mlir's kernel.read_scalar): `v, st := bpf.KprobeRead[T](ctx, n, off)` — off is a constant 0..4095, T is an 8 to 64-bit integer, **st is the raw status** (0 or a negative errno — on x86_64, NULL and user-range addresses give −ERANGE (−34), a fault gives −EFAULT), **the value on failure is 0** (a value of 0 alone cannot distinguish failure — a statement that silently discards it is GB017; `v, _ :=` is accepted). **Only as a top-level statement in the program body** (inside if / loop / subprogram is GB008). The layout and address space of the target are not checked (write off and T from the kernel struct). On all three kernels, the flags / mode of do_sys_openat2's `struct open_how *how` matched the openat2 values, and the user filename gave (0, −34). An integer argument declared as ptr is stopped by the gate's kprobearg (measured with do_sys_poll's ufds on all three kernels). Using `KprobeArg[uintptr]` without the conversion is GB001
- cilium's link.Kprobe silently re-attaches to `__x64_X` when attaching to X fails — gobpf.Load checks before load that X exists and that no alias is used (attach_alias), and `gobpf.AttachKprobe` checks the actual attach target after attaching
- **Functions with compiler suffixes** (`.isra.N`, `.part.N`, `.constprop.N`, `.cold`): 637 to 715 functions on the three kernels exist in kallsyms only under a suffixed name while BTF has only an unsuffixed FUNC (270 common to all three).
  Writing the unsuffixed name is stopped by gobpf.Load (`attach` — not in kallsyms). cilium neither adds nor strips suffixes (it only re-attaches to `__x64_`).
  **A suffixed name (for example `//gobpf:kprobe __do_pipe_flags.part.0`) is accepted for a program that does not read arguments** (it passes the checked Load and AttachKprobe's attach-target check). **A program that reads arguments is stopped by Load** (`kprobearg_unknown` — BTF has no suffixed FUNC; `.isra` is a version with changed arguments, so not being able to read them is correct).
  **The count is not the number of calls of the source function**: `.part.N` is the out-of-line part of gcc's partial inlining, and calls that return in the first half inlined into the caller are not counted (of 33 pipe2(2) calls, the 13 with bad flags do not reach `__do_pipe_flags.part.0`, giving 20 — all three kernels). Suffixed names and whether they exist change with each kernel build (compiler, config)
- A non-root loader needs CAP_BPF + CAP_PERFMON (it goes through perf_event_open — and also depends on kernel.perf_event_paranoid; it was 2 on the three measured kernels)

## devmap and redirect_map (`bpf.DevMap`)

- `var Ports = bpf.DevMap{MaxEntries: N}` — the key is an index (u32) and the value is the ifindex of the target interface (u32). User space sets entries with `Set(k, ifindex)` before attach (a nonexistent ifindex is the kernel's EINVAL — looked up in the netns of the process that Sets)
- The eBPF side is a terminal only: the last statement of the body is `return Ports.Redirect(ctx, k, fallback)` / `return Ports.RedirectIf(ctx, cond, k, fallback, otherwise)` (fallback / otherwise are constant XDP verdicts — not redirect). xdp programs only. There is no devmap Lookup / Update inside a program
- **The return value is the requested action, not the delivery result** — XDP_REDIRECT if the entry exists, fallback if not (unset, after Remove, k ≥ MaxEntries). Forwarding to a veth drops the packet unless the receiving peer has an XDP program or GRO (measured)
- A conditional verdict (`if c { return A }`) and a redirect terminal cannot be mixed — write it with `RedirectIf`

## uprobe (`//gobpf:uprobe` and `bpf.UprobeArg` / `UprobeStr` / `RingBuf.OutputStr`)

- `//gobpf:uprobe <binary path> <symbol>` with `func f(ctx *bpf.UprobeContext)` — **the path is used only at generate time** (relative to the package directory — the binary's sha256 goes into the schema's binary_sha256, and the symbol, calling convention and argument types are checked). The path does not go into the generated files — **the run-time path and PID are loader inputs** (`gobpf.Load(caps, gobpf.WithUprobeTarget(fn, path))` and `gobpf.AttachUprobe(objs, fn, gobpf.UprobeTarget{PID})`)
- **The target must be a C ABI function**: the calling convention is decided from the DW_AT_language of the compilation unit of the target subprogram (the C / C++ family is SysV; **a Go (0x16) function is stopped** — Go's ABIInternal puts arguments in RAX, RBX, RCX, …, so uprobe register reads would give different values; a missing or unknown value is also stopped — the same table as bpf-mlir's). To observe a Go function, target a C entry point exported with cgo `//export`. This is checked both at generate (gobpf's frontend — an early positioned GB008) and before Load (the gate's uprobearg_abi in bpf-mlir — gobpf passes the same fd)
- **Your own binary cannot be a target** — the binary's sha256 goes into the ELF at generate time, and the ELF is embedded in this Go binary, so the hash would be circular
- A uprobe does not fire for inlined calls (only the symbol entry — the fixtures are `noinline`)
- `UprobeArg[T](ctx, n)` follows the same rules as KprobeArg (a mismatch between T and the DWARF type is stopped at generate and before Load). **Go's DWARF result formal_parameters (DW_AT_variable_parameter) are not counted**
- Strings: `st, ok := R.OutputStr(Ev{…}, bpf.UprobeStr(ctx, n))` — helper probe_read_user_str into exactly one `[N]byte` field of Ev with the tag `gobpf:"userstr"`; **st is the raw status** (for non-empty, the length including the NUL; truncated is N; an unreadable pointer is a negative errno (NULL is −14); **an empty string is 1 on 7.1.8 and 0 on 6.12 / 6.6** — test for empty with `st >= 0 && ev.F[0] == 0`). A statement discarding st is GB017. UprobeStr can be written directly only as the second argument of OutputStr
- **The event needs a status field**: exactly one `Status int64 `schema:"status" gobpf:"userstr_status"`` in Ev (missing, two, not int64, or written in the literal is GB016). OutputStr also writes st there. **Unreadable events are also submitted, and the kernel fills the string field with 0** (the memset of bpf_probe_read_user_str — all three kernels) — the Name alone has the same bytes as an empty string, so a reader must not use the Name of an event with `ev.Status < 0`
- **Not sending unreadable events** (bpf-mlir's conditional discard): `st, sent := R.OutputStrOrDiscard(Ev{…}, bpf.UprobeStr(ctx, n))` discards without submitting the event when st < 0 (unreadable pointer — NULL is −14) (sent = false). **The only discard condition is st < 0** — an empty string is submitted (the st of empty is 1 on 7.1.8 and 0 on 6.12 / 6.6 — do not include empty in the condition). Ev does not need a status field (at most one if present — st is written there). A reservation failure is (0, false). The rules are the same as OutputStr (uprobe body, outside loops, a statement discarding st is GB017). On real kernels: with 200 random calls of a C fixture (strings, empty, NULL), events correspond exactly one to one to non-NULL calls, there is no NULL event, and empty is submitted on all three kernels (st is 1 on 7.1.8 and 0 on 6.12 / 6.6) — all three kernels as root, and the non-root table row `ustrdrop`. Example:

  ```go
  st, sent := Names.OutputStrOrDiscard(Ev{Tag: bpf.UprobeArg[uint32](ctx, 2)}, bpf.UprobeStr(ctx, 1))
  if !sent && st < 0 {
  	Fails.AtomicAdd(0, 1) // count the calls that could not be read (no event reaches the ring buffer)
  }
  ```
- Load checks the sha256, symbol, calling convention and arguments with an fd that opened the target (the same fd also for bpf-mlir's gate — requirements.UprobeBinaries), and AttachUprobe attaches with a file offset computed from the same fd and checks the offset in the link info (cilium is not made to reopen the path). A non-root loader needs CAP_SYS_ADMIN

## Tracing hooks (`//gobpf:tracepoint`, `//gobpf:raw_tp`, `//gobpf:kretprobe`, `//gobpf:uretprobe`)

- **tracepoint**: `//gobpf:tracepoint <category>/<event>` with `func f(ctx *bpf.TracepointContext[E])` — E is the event record struct the user declares. The first 8 bytes are the common fields (`_ [8]byte`), and fields to read carry the tag `tp:"<tracefs field name>"` (8 to 64-bit integers only — arrays and `__data_loc` strings cannot be read). **Offsets are E's Go layout** (amd64 — the same as C's natural alignment; the implicit padding before an int64 after an int32 is also the same as C). Reads are only of the form `ctx.Event().F` (each read is one field load — `ctx.Event()` cannot be held in a variable or written), in the program body only
- **generate does not read tracefs** (no root needed; the same source gives the same ELF). Declaration errors (offset, width, sign — forgotten padding, pid_t written as int64, etc.) are **stopped, named, by gobpf.Load before load by checking against the target's tracefs format** (requirements tpfield — confirmed on all three kernels). For **syscalls events** (`syscalls/sys_enter_*`, `sys_exit_*`), ebpf-compile stops wrong offsets at generate time using the kernel structs (syscall_trace_enter / exit — nr at 8, arguments at 16 + 8k, ret at 16)
- **Loading an object with a tracepoint program needs root** (only root can read the tracefs format — for non-root, tpfield is Unknown and **the whole Load stops**, including the other programs in the same object). Attaching (`gobpf.AttachTracepoint` — a perf event on every online CPU) also needs root. To use raw_tp, kretprobe or uretprobe as non-root, put them in a package separate from the tracepoint
- **raw_tp**: `//gobpf:raw_tp <tracepoint>` and `bpf.RawTPArg(ctx, i)` (i is a constant 0 to 11, a raw uint64 value — the type is not checked; an i beyond the tracepoint's argument count is rejected by the kernel at load). Attach with `gobpf.AttachRawTP`
- **kretprobe / uretprobe**: `//gobpf:kretprobe <fn>`, `//gobpf:uretprobe <path> <symbol>` (the same path rules, sha256 and WithUprobeTarget as uprobe) and `ctx.Ret()` — R is a 32 / 64-bit integer (the raw bits of rax — the type is not checked; the value for a void function is meaningless). A kretprobe may name the `__x64_` wrapper (it reads only the return value) — cilium's silent re-attach to an unwritten name is stopped by Load's attach_alias and the post-attach target check. A uretprobe target must be SysV (C / C++) only — a Go function is stopped by generate and by Load's uretprobe_abi
- Non-root loaders: raw_tp and kretprobe need CAP_BPF + CAP_PERFMON; uretprobe additionally needs CAP_SYS_ADMIN (the same as uprobe — non-root table item tracehooks)

## Kernel strings (`bpf.KernelStr`, `RingBuf.OutputKernelStr`)

- A `char *` field of a local kernel type is written as `Filename bpf.KernelStr` (tag `kernel:"filename"`) (`{"kind": "strptr"}` in the schema's kernel_types). **The value cannot be used directly** — assignment to a local variable or reading it is GB001 (KernelStr is not a subset type), comparison is Go's type check (GB000 — an incomparable type), and inside other expressions it is GB027. `p.F` (p a checked kernel pointer) can be written directly **only as the second argument of `RingBuf.OutputKernelStr`**
- `st, ok := R.OutputKernelStr(Ev{…}, p.Filename)` — the same form as OutputStr: helper probe_read_kernel_str into exactly one `[N]byte` (1 ≤ N ≤ 64) field of Ev with the tag `gobpf:"kernelstr"`, and **the raw status** into exactly one int64 field with the tag `gobpf:"kernelstr_status"` (the length including the NUL; a string of length N or more gives N with the field holding the first N−1 characters and a NUL; NULL / a user address is −ERANGE and a fault is −EFAULT (when negative, every byte of the field is 0); **an empty string is 1 on all three kernels**). A statement discarding st is GB017, the field count and types are GB016, inside a loop is GB018, and a reservation failure is (0, false)
- The path is only one level of char * directly under a kernel pointer (char * inside an embedded struct — dentry's d_name.name etc. — and chains of char * do not exist — limits L89). The helper requires a loader with **CAP_PERFMON**, and the ELF requirements use format 15 (the strptr kfield row — before load, checks that the target BTF member is a pointer to a 1-byte integer)
- On real kernels: the filename of linux_binprm in fentry security_bprm_check, with 4 exec path lengths of your own helper (around 25, 31, 32, 48 bytes), on all three kernels as root (6.12 / 6.6 in bpf-mlir's test VM kernels — a kernel without CONFIG_SECURITY has no attach target, and gobpf.Load stops before load, naming it) and on 7.1.8 as non-root ({bpf, perfmon} etc.) — 31 bytes gives St 32 without truncation, 32 bytes or more gives St 32 with the first 31 bytes and a NUL, exactly one record per exec

## struct_ops (`bpf.TCPCongestionOps`, `//gobpf:struct_ops <map> <member>`)

- `var CC = bpf.TCPCongestionOps{Name: "<name>"}` (one per package; the name is 1 to 15 characters of `[A-Za-z0-9_.]` — the kernel's TCP_CA_NAME_MAX 16 minus the terminator) and, per member, `//gobpf:struct_ops CC <member>` + `func f(ctx *bpf.StructOpsContext) …`. The members are init (no result), ssthresh (uint32), undo_cwnd (uint32) and cong_avoid (no result) — **ssthresh, undo_cwnd and cong_avoid are required** (a missing one stops at generate — before the kernel's tcp_validate EINVAL)
- `gobpf.Load` writes the program fds into the map but **does not register** (the ELF's `.struct_ops.link` — BPF_F_LINK). `gobpf.AttachStructOps(objs, &CC)` registers it (checking that the name is in `/proc/sys/net/ipv4/tcp_available_congestion_control`), and closing the link unregisters it (unregistration can be delayed — it waits until the name leaves the list). EEXIST if the same name exists
- **Registration is a system-wide name** — sockets in every netns can choose it with setsockopt TCP_CONGESTION (flags 0 — choosing needs CAP_NET_ADMIN); the host default (net.ipv4.tcp_congestion_control) is not changed. Choosing an unregistered name makes the kernel try a module autoload (request_module). The repository's tests register only inside a VM (the two markers of internal/vmguard)
- A non-root loader needs CAP_BPF for the map and CAP_PERFMON for the programs; creating the link has no capability check
- Member arguments: read fields with `if sk := bpf.StructOpsArg[TcpSock](ctx, 0); sk != nil { … }` (TcpSock is a local type with the tag `kernel:"tcp_sock"` — the verifier promotes the kernel's `struct sock *` to tcp_sock; it may always be NULL) and **write with `sk.SndCwnd = n`** (ebpf.kfield.store — struct_ops only; the kernel decides which fields are writable — limits L88). Integer arguments are `x := bpf.StructOpsArgInt[uint32](ctx, i)` (cong_avoid's 1 = ack, 2 = acked)

## ext (`//gobpf:ext <program> <function>` — freplace)

- `//gobpf:ext tgt g` + `func rep(ctx *bpf.ExtContext) T` — replaces the `//gobpf:global` function `g` that a non-ext program `tgt` of the same package calls (directly or through subprograms). The result type T is identical to `g`'s result type, and arguments are `bpf.ExtArg[Ti](ctx, i)` (Ti identical to the type of `g`'s i-th argument). `g`'s arguments and result are integers only (up to 5 arguments)
- `gobpf.Load` works in two steps (load without the ext → load the ext with `tgt` of the same Load as the replacement target, not attached). Attaching with `gobpf.AttachExt(objs, rep)` replaces **only the calls of `g` inside `tgt`** with rep (other programs calling the same `g` are unchanged). Closing the link restores the original. After attaching, the id of the link's replacement-target program is checked against `tgt`'s id (the function name is not checked — at load time cilium looks it up by name from `tgt`'s BTF, and the kernel checks the types)
- **The replacement target can only be a program of the same Load** — there is no API that takes the fd of another program (a program of another process). The requirements extret / extarg are checked against the BTF of `tgt`'s function in the embedded ELF (a replacement target outside the same object stops with ext_target_unknown)
- The kernel does not check the return width or integer sign (gobpf forces identity with the Go types). The schema's args / ret are unsigned of the same width (the integers ebpf-compile emits into a global function's BTF are unsigned)
- A non-root loader needs CAP_BPF + CAP_PERFMON (loading EXT) plus the capabilities of the replaced kind (CAP_NET_ADMIN for xdp — CAP_SYS_ADMIN also suffices). **CAP_SYS_ADMIN is not needed** — the BTF of the replacement target comes from the cache of programs cilium loaded itself, and BPF_BTF_GET_FD_BY_ID, which needs CAP_SYS_ADMIN, is not called (gobpf only uses programs of the same Load as targets, so this is the only path — {bpf, net_admin, perfmon} passed on 7.1.8)

## cgroup_array (`bpf.CgroupArray`)

- `var CG = bpf.CgroupArray{MaxEntries: N}`. User space uses `CG.Set(k, fd)` (an fd of an opened cgroup v2 directory into slot k — the kernel holds a reference to the cgroup, so the fd can be closed afterwards) and `CG.Clear(k)`
- On the eBPF side, `st := CG.TaskUnder(k)` (1 if the current task is in slot k's cgroup or a descendant, 0 if outside) and `st := CG.SkbUnder(ctx, k)` (tc programs — the cgroup of the skb's socket); an empty slot is −EAGAIN (−11), out of range is −E2BIG (−7), and SkbUnder gives −ENOENT for an skb without a full socket. The index may be a value
- **On kernel 6.x, TaskUnder is only for tracing kinds (fentry etc.)** (for xdp etc. the verifier rejects it at load — 7.1.8 also allows other kinds). The tc test run's skb has a dummy socket in the calling task's cgroup (as observed)
- A non-root loader needs CAP_BPF for the map plus the capability of the program type (CAP_PERFMON for fentry, CAP_NET_ADMIN for tc). Creating a test cgroup and putting a child into it need permissions on the cgroup directory

## user_ringbuf (`bpf.UserRingBuf`)

- `var In = bpf.UserRingBuf[Req]{MaxEntries: 4096}` (Req is a record of integer fields; MaxEntries is a power of two ≥ 4096). User space uses `w, _ := gobpf.NewUserRingWriter(&In)`, `w.Write(Req{…})` (`gobpf.ErrUserRingFull` if there is no room — it cannot write until the eBPF side's Drain reads) and `w.Close()`
- The eBPF side uses `n := In.Drain(onReq)` (program body only — the return value is the number of samples consumed (including the one stopped at) or a negative errno), and the callback is `func onReq(r Req, ok bool) bool` in the same package — **ok tells whether the sample covers Req** (fields of a short sample are not silently zeroed); returning true stops there
- **The callback cannot have branches** (a bpf-mlir constraint) — the body is arithmetic, `bpf.Global` Add / Load, `bpf.KtimeNs` and an if that wraps only a Global Add (lowered to a branchless select), ending with `return <bool>`. Maps cannot be used — add results to a global
- The writer writes a sample's 8-byte header and body (rounded up to 8 bytes) before advancing the producer position — 256 samples of 16 bytes fit in a 4096-byte ring. A non-root loader needs CAP_BPF for the map and helper, plus the capability of the draining program's type (CAP_NET_ADMIN for xdp)

## syscall (`bpf.SyscallContext`)

- `func f(ctx *bpf.SyscallContext) bpf.SyscallRet` (no directive) — **not attached**. User space calls BPF_PROG_TEST_RUN with `gobpf.RunSyscall(objs, fn, ctx)`, passing ctx (a byte slice) and receiving retval (u32) and the ctx the kernel wrote back
- ctx is read with `bpf.SyscallLoad[T](ctx, off)` (T is an 8 to 64-bit integer, little endian; off is a constant multiple of T's width, off + width ≤ 65535). **The ctx you pass must be at least as long as the farthest byte the program reads** (shorter makes the test run EINVAL). The return value may be a computed `bpf.SyscallRet(…)`
- **Calling bpf()** (bpf-mlir's sys.bpf / sys.close): `st := bpf.SysBpf(ctx, cmd, attr)` where cmd is one of the constants `bpf.SysBpfMapCreate`, `bpf.SysBpfMapGetFdByID`, `bpf.SysBpfMapFreeze` (the three whose attr has no pointer field), and attr is a literal of a named struct of this package. **The attr layout is the user's responsibility** — nobody checks that the field order matches the cmd's struct in union bpf_attr (a wrong order is silently a different attr — a different status or a different map). **Compile stops only on size** (map_create 80, map_freeze 8, map_get_fd_by_id 16 bytes — up to the first pointer field of the cmd's struct, bpf-mlir's SysBpfAttr.def — beyond that, a Go-positioned `ebpf-compile: error:`). The status is raw: map_create / get_fd_by_id give a new fd (in **the fd table of the process that called test run** — the caller closes it), map_freeze gives 0 (**the second freeze of a frozen map is −EPERM** — the write-permission check comes first), and get_fd_by_id gives −EPERM for a loader without CAP_SYS_ADMIN (before checking whether the ID exists). `st := bpf.SysClose(ctx, fd)` gives 0 or −EBADF. Only top-level statements in the body (inside if, loop or an expression is stopped); a statement discarding st is GB017
- On real kernels: the status of 7 programs (map_create, −22 with key 8, freeze's 0 and the second's −1 and EPERM on updating the frozen map, close's 0 / −9 and freeze of a closed fd −9, get_fd_by_id's fd and −2 for a removed ID, an 80-byte record, a token fd @76 giving an fd on 7.1.8 / 6.12 and −22 on 6.6), the map info of the fd in the process that called test run, and the ID disappearing after close agree with the model on all three kernels as root (6.12 / 6.6 in bpf-mlir's test VM kernels); on 7.1.8 non-root, from {bpf, perfmon} (get_fd_by_id gives −1 / −1 in sets without CAP_SYS_ADMIN)
- There are no ctx writes or kfuncs (limits L83). A non-root loader needs only CAP_BPF (a program using SysBpf also needs CAP_PERFMON — helper bpf_sys_bpf)

## kprobe_session (`bpf.KprobeSessionContext`)

- `func f(ctx *bpf.KprobeSessionContext) bpf.KprobeSessionRet` with `//gobpf:kprobe_session <kernel function>` — the same program runs at the function's entry and return (a kprobe.multi link). `ctx.IsReturn()`, `ctx.Cookie()` / `ctx.SetCookie(v)` (8 bytes set at entry are read at return — the same methods as fsession)
- The return value is the constant `bpf.KprobeSessionRun` (0) / `bpf.KprobeSessionSkipReturn` (1) — **returning 1 in the entry run skips the return run** (the return run's return value is not used). On reentry (firing inside another BPF program), the kernel does not run the program and skips the return too (counted in misses)
- Attach with `gobpf.AttachKprobeSession(objs, fn)` — after attaching, only the function count of 1 is checked (the link info has no name). **7.1.8 only** — on 6.12 / 6.6, gobpf.Load's check stops before load (kfunc_sig on 6.12; attach_type and kfunc_sig on 6.6)
- A non-root loader needs CAP_BPF + CAP_PERFMON (the same as kprobe; creating the link needs no additional capability)

## raw_tp_writable (`bpf.RawTPWritableContext`)

- `func f(ctx *bpf.RawTPWritableContext)` (no result) with `//gobpf:raw_tp_writable <tracepoint>`. Only the kernel's DEFINE_EVENT_WRITABLE tracepoints can be attached (others give −EINVAL at attach — the program's buffer access exceeds the writable size writable_size)
- `ctx.Buffer()` / `ctx.SetBuffer(v)` read and write the int32 at offset 0 of the writable buffer (program body only, outside loops). The buffer of vmlinux's **bpf_test_finish** is BPF_PROG_TEST_RUN's err, and **the written value becomes the return value of the test run syscall** (writing −33 makes the test run EDOM)
- **The program's write affects every firing of the tracepoint** — bpf_test_finish fires on every skb / xdp / tracing test run in the system, so filter on your own tgid (`bpf.CurrentPidTgid() >> 32`) before writing
- Attach with `gobpf.AttachRawTPWritable(objs, fn)` — after attaching, the link's raw tracepoint name is checked. There is no test run (the kernel has no raw_tp_writable test run). A non-root loader needs CAP_BPF + CAP_PERFMON

## fmod_ret (`bpf.FmodRetContext`)

- `func f(ctx *bpf.FmodRetContext) bpf.FmodRet` with `//gobpf:fmod_ret <kernel function> nargs=<N>`. Arguments are top-level `a := bpf.FmodRetArgInt[T](ctx, i)` in the body (integers only — T has the same width and sign as the function argument, checked at load by farg), and nargs is the function's argument count (checked by retsig)
- **A return value of 0 runs the original function; a non-zero value skips the original function and makes that value the function's return value** (the kernel's trampoline — there is no range check of the value). The return value may be a computed expression (`return bpf.FmodRet(a + 41)`). In a final `if c { return A }; return B`, both A and B are evaluated before choosing — only variables, constants, type conversions and + − * & | ^
- Attach with `gobpf.AttachFmodRet(objs, fn)` — after attaching, the link's attach-target name is checked against the directive. **The function to attach is not restricted** — only functions the kernel allows (the error-injection list, security_ functions, the kernel's fmodret set) can be attached, and others give "not modifiable" at load. Attaching a program that returns a value that skips the original function to a function on a real path changes system behavior — the choice is the caller's
- Try it with bpf_modify_return_test (called only by the tracing test run — fmod_ret test runs of other processes also call it, so filter on tgid). A non-root loader needs CAP_BPF + CAP_PERFMON

## lwt_seg6local (`bpf.Seg6LocalContext`)

- `func f(ctx *bpf.Seg6LocalContext) bpf.Seg6Action` (no directive). Reads `ctx.Len()`, `ctx.Mark()`, `ctx.Priority()`, `ctx.Protocol()` (the ethertype as be16 — IPv6 is 56710 = 0xdd86), `ctx.Ifindex()` (the receiving device) and writes `ctx.SetMark(v)`, `ctx.SetPriority(v)`. Verdicts are `bpf.Seg6OK` (look up and forward on the next segment) / `bpf.Seg6Drop`
- Attach with `gobpf.AttachSeg6Local(objs, netnsPath, sid, oif, fn)` — adds the route `<sid>/128 dev <oif> encap seg6local action End.BPF` to the netns netnsPath. On the thread that did setns, **the same guard as netfilter and lwt runs just before sending** (the thread's netns equals the given netns and differs from the host's /proc/1/ns/net — otherwise nothing is sent), and Close of the returned value removes the route the same way
- **The kernel decrements the SRH's segments_left by 1 and sets the destination to the next segment before the program** — for a packet whose SRH has segments_left 0, the program does not run (the kernel drops it first). **A mark write affects the fwmark of the lookup after End.BPF** (a policy-routing rule can choose the exit)
- **There is no test run** — to try it, pass real packets through the route (measured by injecting into the lo of a test netns with AF_PACKET and observing on an exit dummy tap). Forwarding needs net.ipv6.conf.all.forwarding=1 in the netns
- A non-root loader needs CAP_BPF + CAP_NET_ADMIN to load; adding the route needs CAP_NET_ADMIN in the netns and CAP_SYS_ADMIN for setns. There are no seg6 helpers, redirect or packet windows (limits L79)

## lwt_in / lwt_out / lwt_xmit (`bpf.LWTInContext` etc.)

- `func f(ctx *bpf.LWTOutContext) bpf.LWTAction` (also LWTInContext and LWTXmitContext, no directive). `ctx.Len()` (the skb len — from the IP header) and `ctx.Check(off, n)` (packet window reads only — **data starts at the IP header**; there is no L2). Verdicts are `bpf.LWTOK` / `bpf.LWTDrop` (xmit redirect is not emitted)
- Attach with `gobpf.AttachLWTRoute(objs, netnsPath, dst, oif, fnIn, fnOut, fnXmit)` — adds the route `<dst> dev <oif> encap bpf [in …] [out …] [xmit …]` to the netns netnsPath (unused stages are nil). On the thread that did setns, **the same guard as netfilter runs just before sending** (the thread's netns equals the given netns and differs from the host's /proc/1/ns/net — otherwise nothing is sent). Close of the returned value removes the route the same way (RTM_DELROUTE)
- **A drop is a send error**: on LWTDrop in out / xmit, the kernel drops the skb and returns −EPERM to the sender (a UDP sendto gives EPERM)
- The test run's data starts at the IP header (len = frame length − 14)
- lwt_in runs at the lookup of the receive route (it needs a forwarding topology — only the test run was measured)
- A non-root loader needs CAP_BPF + CAP_NET_ADMIN to load and test run (constant-offset windows); adding the route needs CAP_NET_ADMIN in the netns and CAP_SYS_ADMIN for setns

## netfilter (`bpf.NetfilterContext`)

- `func f(ctx *bpf.NetfilterContext) bpf.NFAction` (no directive). `ctx.Hook()` / `ctx.PF()` (u8 of nf_hook_state), `ctx.SkbLen()` (the sk_buff len) — CO-RE reads through kernel pointers (nf_hook_state and sk_buff are added to the schema's kernel_types). Verdicts are `bpf.NFDrop` / `bpf.NFAccept`
- Attach with `gobpf.AttachNetfilter(objs, fn, netnsPath, link.NetfilterProtoIPv4, link.NetfilterInetLocalIn, priority)` — **the kernel attaches to the hook of the netns of the thread that creates the link**, so gobpf attaches on a thread that did setns into netnsPath, and **just before attaching checks that the thread's netns inode equals the given netns and differs from the host netns (/proc/1/ns/net), and does not attach otherwise** (it also does not attach when not root and /proc/1/ns/net cannot be read). priority must not be INT_MIN / INT_MAX
- The test run's default ctx is hook LOCAL_OUT (3) and pf IPv4 (2); data starts at the IP header (less than 20 bytes is EINVAL)
- A non-root loader needs CAP_BPF + CAP_NET_ADMIN + **CAP_PERFMON** (the verifier requires CAP_PERFMON or CAP_SYS_ADMIN for reads through state / skb)

## flow_dissector (`bpf.FlowDissectorContext`)

- `func f(ctx *bpf.FlowDissectorContext) bpf.FlowAction` (no directive). Verdicts are `bpf.FlowOK` (use flow_keys as the flow key), `bpf.FlowDrop` and `bpf.FlowContinue` (return to the kernel's dissector) — **one program has only the two verdicts of the final `if c { return A }; return B`** (split the program to use all three)
- The 14 scalar fields of flow_keys are read and written with `ctx.Nhoff()` / `ctx.SetThoff(v)` etc. (widths as in the UAPI — Nhoff, Thoff, AddrProto, NProto, Sport, Dport are uint16; IsFrag, IsFirstFrag, IsEncap, IPProto are uint8; IPv4Src, IPv4Dst, Flags, FlowLabel are uint32). **Before the program, the kernel zeroes flow_keys and sets NProto (the raw ethertype), Nhoff, Thoff (= Nhoff) and Flags, and afterwards it clamps Nhoff and Thoff**. Network-order fields keep their byte order — writing the value of the packet's `w.LE16` / `w.LE32` as is copies the bytes
- The packet is read only through `ctx.Check(off, n)` windows. The test run's data starts at the Ethernet header (Nhoff 14). **With constant-offset windows only, it can be loaded with CAP_BPF + CAP_NET_ADMIN** — a variable offset also needs CAP_PERFMON
- Attach with `gobpf.AttachNetNs(objs, fn, netnsPath)` — **one link per netns** (a second is E2BIG); a direct attach (BPF_PROG_ATTACH) to a netns that has a link is EEXIST; **attaching to the host's init_net overrides the dissection of every netns** (while one is on init_net, attaching to other netns is EEXIST)

## sk_reuseport and reuseport_sockarray (`bpf.SkReuseportContext`, `bpf.ReuseportSockArray`)

- `func f(ctx *bpf.SkReuseportContext) bpf.SKAction` (no directive). `ctx.Len()` (for UDP, the 8-byte header + payload), `ctx.EthProtocol()` (as be16 — IPv4 is 8), `ctx.IPProtocol()`, `ctx.BindInany()`, `ctx.Hash()` (the 4-tuple hash — depends on the kernel's random secret)
- `var Socks = bpf.ReuseportSockArray{MaxEntries: N}` — the eBPF side has only `Socks.Select(ctx, k)` (raw status — 0; an empty slot or out of range is −ENOENT; a socket of another group is −EBADFD, etc.). Return SKPass after selecting too; SKPass without selecting is the kernel's hash selection; SKDrop gives it to no one (UDP gets ICMP port unreachable, a TCP SYN gets ECONNREFUSED). Select is top-level only (inside a loop is GB018)
- User space: `Socks.Set(k, fd)` (only a bound SO_REUSEPORT socket — before bind, or a socket without SO_REUSEPORT, is EINVAL), `Socks.Cookie(k)` (the socket cookie or ErrKeyNotExist), `Socks.Remove(k)`. **Closing a socket of the group removes its slot**
- Attach with `gobpf.AttachReuseport(objs, fn, fd)` (SO_ATTACH_REUSEPORT_EBPF — on the fd of a bound socket of the group; Close does SO_DETACH_REUSEPORT_BPF). **It runs only for the selection in the attached socket's SO_REUSEPORT group**. The group releases the program when every socket of the group is closed
- A non-root loader needs **only CAP_BPF** (SK_REUSEPORT is outside is_net_admin_prog_type — the kernel comment "equivalent to SOCKET_FILTER"; {bpf} passed every stage in the non-root table), and attaching needs no capability. There is no migrate, cookie, or selection from sockmap / sockhash (limits L75)

## sk_lookup (`bpf.SkLookupContext`)

- `func f(ctx *bpf.SkLookupContext) bpf.SKAction` (no directive). `ctx.Family()`, `ctx.Protocol()`, `ctx.LocalPort()` (host order), `ctx.LocalIP4()` (network order — 127.0.0.1 is 0x0100007F), and **`ctx.RemotePort()` is a be16 uint16** (network order as is — port 7201 is 0x211C; do not convert on the Go side)
- Attach with `gobpf.AttachNetNs(objs, fn, netnsPath)` (opens the netns file and links — `/var/run/netns/<name>` etc.). **It runs only for lookups in the attached netns**: TCP at the listener lookup (at SYN), UDP for a datagram to an unconnected socket — it also runs at the lookup for delivering the ICMP port unreachable error of a UDP drop (looking for the sender's socket). It does not run for datagrams to a connected UDP socket or for segments of an established TCP connection
- SKDrop makes the lookup "no socket" (TCP gets an RST — connect gives ECONNREFUSED; UDP gets ICMP port unreachable); SKPass is the normal lookup
- **Selecting a socket** (bpf-mlir's sk.assign): `st, found := Socks.Assign(ctx, k, flags)` (SockMap or SockHash[K]) looks up the socket in slot k and, if present (found), selects it as the result of this lookup — returning SKPass delivers to the selected socket (the destination address / port is not rewritten — the local port of the accepted socket is the dialed port). st is the raw status of the helper sk_assign: 0 means selected; a protocol mismatch is −EPROTOTYPE; a family mismatch (an IPv6 lookup for an AF_INET socket) is −EAFNOSUPPORT; a refcounted socket (an ESTABLISHED TCP — sockmap restricts TCP to ESTABLISHED / LISTEN, so a non-LISTEN TCP returns on the refcount arm) is −ESOCKTNOSUPPORT; already selected without SkAssignReplace is −EEXIST. An empty slot is (0, false). flags are constants (`bpf.SkAssignReplace`, `bpf.SkAssignNoReuseport`, `|`); a statement discarding st is GB017, inside a loop is GB018, program body only (the sk_lookup context cannot be passed to a subprogram). The socket reference does not appear in Go (the frontend assembles lookup, check, select and release)
- To select **a reuseport socket**, SkAssignNoReuseport is needed (without it the test run gives −EOPNOTSUPP — the selection itself returns 0). Creating a sockmap / sockhash needs CAP_NET_ADMIN (CAP_SYS_ADMIN also works on 7.1.8 / 6.12)
- On real kernels: the status, found and cookie of 12 test-run arms (success, protocol / family mismatch, refcount, the second EEXIST, replace, empty slot, reuseport's EOPNOTSUPP and no_reuseport, sockhash), and real steering in a test netns (a connect to a port without a listener is accepted by the selected listener with the dialed local port, and ECONNREFUSED after detaching), agree with the model on all three kernels as root (6.12 / 6.6 in bpf-mlir's test VM kernels); on 7.1.8 non-root, from {bpf, net_admin}
- Attaching increments the kernel's static key (bpf_sk_lookup_enabled), adding a "does a run_array exist" branch to lookups in every netns (the program runs only in the attached netns). A non-root loader needs CAP_BPF (load)

## cgroup_sockopt (`bpf.CgroupSetsockoptContext` / `bpf.CgroupGetsockoptContext`)

- `func f(ctx *bpf.CgroupSetsockoptContext) bpf.CgroupAction` / `func f(ctx *bpf.CgroupGetsockoptContext) bpf.CgroupAction` (the direction is the type — no directive). `ctx.Level()`, `ctx.Optname()`, `ctx.Optlen()` are int32, and `ctx.SetOptlen(v)`
- **A setsockopt program runs before the kernel's handler**: the value written into the optval window (`if w, ok := ctx.Check(off, n); ok { … w.SetLE32(0, v) }` — the window length is max(16, optlen)) is passed to the handler. `SetOptlen(-1)` skips the handler and the syscall returns 0, `SetOptlen(0)` passes the user's original value, and longer than the window or below −1 is EFAULT
- **A getsockopt program runs after the handler**: optval is a copy of the value the handler returned (the window length is the length the user passed), and window writes are visible to the user. `Optlen()` is the length the handler returned, `SetOptlen(0)` does not copy back, and negative or beyond the user's length is EFAULT
- optval writes are only on a window at the top level of the program body (inside a loop is GB018; a window passed to a subprogram is GB013). There are no level / optname writes (limits L73)
- Attach with `gobpf.AttachCgroup` (AttachCGroupSetsockopt / AttachCGroupGetsockopt). **Only the programs of the cgroup of the task that created the socket run**. CgroupDeny gives EPERM (for getsockopt, after the handler's result — the user's buffer stays as the handler wrote it)
- A non-root loader needs CAP_BPF + CAP_NET_ADMIN (is_net_admin_prog_type at load)

## cgroup_sysctl (`bpf.CgroupSysctlContext`)

- `func f(ctx *bpf.CgroupSysctlContext) bpf.CgroupAction` (no directive). `ctx.Write()` is 1 for a write and 0 for a read; `ctx.FilePos()` / `ctx.SetFilePos(v)` is the file position
- `ctx.SetNewValue("63\n")` replaces the value of a write — **the value must be a string constant** (1 to 64 bytes, without adding a trailing NUL — limits L72); the return value is the raw status (0 on a write call, **−EINVAL on a read call**). A replaced write(2) returns the length of the replacement. Only at the top level of the program body (inside a loop is GB018)
- Attach with `gobpf.AttachCgroup` (attach type AttachCGroupSysctl). **Only the programs of the cgroup of the reading / writing task run** — CgroupDeny makes the read / write EPERM (proc_handler is not called)

## iter (`//gobpf:iter bpf_map_elem <map>`, `bpf.IterContext`, `bpf.SeqFile`)

## Socket and cgroup (`bpf.SocketFilterContext`, `CgroupSKBIngressContext` / `EgressContext`, `CgroupSockContext`, `SockAddrContext`, `SockOpsContext`)

## Local storage maps (`bpf.TaskStorage[V]`, `SKStorage[V]`, `CgrpStorage[V]`, `InodeStorage[V]`)

- Declare with `var Seen = bpf.TaskStorage[V]{}` (no key or MaxEntries — the kernel object is the key; the schema has max_entries 0 and flags BPF_F_NO_PREALLOC). V is the same as an Array value (a 32 / 64-bit integer or a record)
- The eBPF side: `if v := Seen.Get(owner, bpf.Create); v != nil { … }` (creates with 0 if absent — the same borrow rules as the checked arm of Lookup), `bpf.NoCreate` (nil if absent), `st := Seen.Delete(owner)` (raw status — −ENOENT if absent; a statement discarding it is GB017). **owner is a checked pointer of a local kernel type** (`if p := bpf.FentryArg[T](ctx, i); p != nil`, `p := bpf.TPArg[T](ctx, i)`) whose `kernel:"<struct>"` on T is the kind's struct (task_struct, sock, cgroup, inode — otherwise GB027). It cannot be used inside a loop (GB008)
- The user-space side: `Seen.GetFD(fd)` / `Seen.DeleteFD(fd)` — the key is the owner's fd (a pidfd for a task (`unix.PidfdOpen` — the process leader, not a thread), the socket fd for a socket, the cgroup directory fd for a cgroup). The kernel removes the value when the object ends
- **Which program types can use it is up to the kernel**: task / cgrp can be used from tracing (fentry, tp_btf), **sk from fentry / fexit (not tp_btf)**, and **inode only from lsm** — from a go tracing program, load stops. cgrp_storage is available from kernel 6.2
- On real kernels: task (the child of fentry wake_up_new_task — the parent's tgid and count through the child's pidfd) and sk (fentry tcp_sendmsg — the send count, Delete twice (0 and −ENOENT) on a send of length 7, re-creation, the count seen with NoCreate) agree with the model on all three kernels as root; task and cgrp tp_btf owners (sched_process_fork, cgroup_mkdir) on 7.1.8 / 6.12 (on 6.6 a tp_btf that reads a pointer argument is stopped by arg_nullable — use an fentry owner on 6.6)
- A non-root loader needs CAP_BPF + CAP_PERFMON (the same as fentry — 7.1.8)

## lsm and lsm.s (`//gobpf:lsm`, `//gobpf:lsm_s`, `bpf.LSMContext`, `bpf.LSMArg[T]`, `bpf.LSMArgInt[T]`, `bpf.LSMRet`)

- `//gobpf:lsm <hook>` with `func f(ctx *bpf.LSMContext) bpf.LSMRet` (lsm.s uses `//gobpf:lsm_s <hook>` and `*bpf.LSMSleepableContext` — a mismatch between the type and the directive is GB008). The hook's arguments cannot be read (ctx has no methods — go does not expose them; bpf-mlir has lsm_cgroup arguments (trace_lsm_cgroup + farg)), and the return value is `bpf.CgroupDeny` (deny the operation with EPERM) / `bpf.CgroupAllow`. ## Keyless maps (`bpf.Queue[V]`, `bpf.Stack[V]`, `bpf.BloomFilter[V]`)

- Declare with `var Q = bpf.Queue[V]{MaxEntries: N}`, `bpf.Stack[V]{…}`, `bpf.BloomFilter[V]{MaxEntries: N, ZeroSeed: true}` (V is an 8 to 64-bit integer — bpf-mlir's schema rejects records)
- The eBPF side uses raw status: `st := Q.Push(v, bpf.PushAny)` (−E2BIG when full), `bpf.PushExist` (when full, drops the oldest element and pushes — for both queue and stack), `v, st := Q.Pop()` / `Peek()` (when empty, v is 0 and st is −ENOENT), `st := B.Push(v)`, `st := B.Peek(v)` (0 means "may be present" — false positives are possible; −ENOENT means absent). - On real kernels: −E2BIG when full, overwrite with exist, FIFO / LIFO, −ENOENT when empty, present and absent bloom values (zero_seed), and round trips with user space agree with the model on all three kernels as root. Creating the map needs CAP_BPF, and loading and test-running the xdp program needs CAP_NET_ADMIN or CAP_SYS_ADMIN (7.1.8 non-root)

## map-in-map (`bpf.ArrayOfMaps[K, V]`, `bpf.HashOfMaps[OK, K, V]`, `bpf.InnerMap[K, V]`)

- Declare with `var A = bpf.ArrayOfMaps[K, V]{MaxEntries: N, Inner: bpf.InnerSpec{Kind: bpf.InnerHash, MaxEntries: M}}` (the type arguments are the inner K / V — K is u32 and V is a 32 / 64-bit integer; Kind is one of the constants InnerArray, InnerHash, InnerLRUHash); `bpf.HashOfMaps[OK, K, V]` has the outer key OK. The inner template is the schema map `<outer>_inner` (not a map in the ELF's .maps)

There is no outer Update / Delete (bpf-mlir rejects them). **AtomicAdd on a hash inner map applies only when the key exists** (otherwise nothing happens — observed)

The kernel restricts inserted maps to the template's shape (otherwise −EINVAL)
- gobpf.Load's check compares the declared Inner with the innermap row of the ELF requirements (format version 12) and names a mismatch before load (`map A: inner map template declared …, but the ELF has …`)
- On real kernels: an outer miss, an inner key miss, inner ops, user-space NewInner / Set / Get and replacement agree with the model on all three kernels as root. Creating the maps uses unprivileged types (an LRU inner needs CAP_BPF), and the xdp test run needs CAP_NET_ADMIN or CAP_SYS_ADMIN

## sockmap and sk_skb (`bpf.SockMap`, `bpf.SockHash[K]`, `//gobpf:sk_skb`, `gobpf.AttachSockmap`)

- `var Socks = bpf.SockMap{MaxEntries: N}` (key u32) / `bpf.SockHash[K]{MaxEntries: N}` (K an integer), with user-space `Socks.Set(k, fd)` and `Socks.Remove(k)` (the kernel accepts only TCP in ESTABLISHED / LISTEN etc. — an unconnected TCP is EOPNOTSUPP, a non-socket fd is ENOTSOCK)

Redirect is asynchronous through a work queue — the return value is acceptance of the request
- The program runs only on receive for sockets in the map. **The program applies to sockets Set after attach** (the kernel binds the map's programs to a socket when the socket is inserted)

SKDrop drops the message and sendmsg gets EACCES — **a drop is sticky: later sends on a socket that dropped once are dropped with EACCES without running the program** (the kernel's tcp_bpf_send_verdict does not reset the verdict after a drop — it is not a per-message verdict); terminals are `Socks.MsgRedirect` / `MsgRedirectIf` (egress only to a TCP destination). ctx has `Size`, `Family`, `RemoteIP4`, `LocalIP4` (network-order u32), `RemotePort` (**as the kernel converts it — the network-order 16 bits shifted left by 16**) and `LocalPort` (host order)

Attach sock_ops to a test cgroup with `gobpf.AttachCgroup`
- On real kernels: on TCP connections over 127.0.0.1 from child processes in a test cgroup, sock_ops insertion (any, and EBUSY with noexist), sk_msg pass / drop (EACCES and stickiness), redirect ingress and the byte order of ctx addresses and ports agree with the model on all three kernels as root (6.12 / 6.6 in bpf-mlir's test VM kernels) — on the third run (deviations outside the predictions of the first and second runs are recorded)
- Attach with `gobpf.AttachSockmap(objs, fn)` — **BPF_PROG_ATTACH** (bpf-mlir's livecaps.AttachSockmapProgAttach — sockmap links exist from 6.10). Close detaches; it also detaches when the map disappears without closing. The checking loader declaration is `gobpf.LoaderDecl` (sockmap_attach prog_attach — the plain cilium v0.22 link declaration stops before load on 6.6)

## Ring buffer reservation (`RingBuf.Reserve`, `Submit`, `Discard`)

- `if e, ok := Events.Reserve(); ok { e.F = v; …; Events.Submit(e) } else { … }` — the reservation handle `e` is created only in the if's init statement and **used only in assignments to integer fields `e.F = v`, whole-record assignment `*e = Ev{…}`, and as the argument of `Submit(e)` / `Discard(e)`** (it cannot be read from, stored in another variable, passed to a function, used in the else arm, or reserved inside a loop — the frontend's GB005 / GB018)
- **Exactly one Submit or Discard on every path of the present arm** — double use, a missed one, or an assignment after consumption are stopped by bpf-mlir's ownership check at go generate, with the error at the Go file:line (for example `main.go:17:3: ebpf-compile: error: 'ebpf.ringbuf.submit' op uses a ring buffer reservation after it was submitted or discarded on this path`). The frontend does not check the consumption count (it does not keep a second implementation)
- A discarded event does not reach the reader, but its ring space is used until the reader reads past it — in a 4096-byte ring, 170 events of 16 bytes (24 bytes with the header) can be reserved if the reader does not read (bpf-mlir's rule — one less than the size)
- On real kernels: per-field writes, whole-record writes, conditional submit / discard (discarded events do not reach the reader) and the count of failed reservations (170 / 30) agree with the model in xdp test runs on all three kernels as root; a non-root loader needs CAP_BPF + CAP_NET_ADMIN (or CAP_SYS_ADMIN)

## sched_act (`bpf.TCActContext`, `bpf.TCActAction`)

## usdt (`//gobpf:usdt`, `bpf.USDTContext`, `bpf.USDTArg[T]`, `gobpf.AttachUSDT`)

- `//gobpf:usdt <binary path> <provider>:<name>` with `func f(ctx *bpf.USDTContext)`, `v, st := bpf.USDTArg[T](ctx, n)` (n is a constant 1..12; st is the raw status — 0 is success, −ENOENT if the point has no spec), and `bpf.ProbeTargetIndex(ctx)` is the point index (in the order of the binary's notes)
- **generate reads the binary's notes**: whether the point exists, consistent semaphores per point, and the USDTArg argument count and the size / sign of the types (the note's `<±size>@`). The binary is the fd of Load's `WithUprobeTarget`

- On real kernels: the 3 points of us:hit in your own fixture (memory and constant locations) and the value of the semaphore-guarded us:guarded, the status, the point index and the PID filter agree with the model on all three kernels as root; the semaphore is 0 before attach, 1 while attached and 0 after detach (points after detach are not counted); a non-root loader needs CAP_BPF + CAP_PERFMON + CAP_SYS_ADMIN

## ksyscall (`//gobpf:ksyscall`, `bpf.KsyscallContext`, `bpf.KsyscallArg[T]`, `gobpf.AttachKsyscall`)

- On real kernels: the getppid count and prctl arguments 1 to 5 agree with the model on all three kernels as root

## XDP forwarding maps (`bpf.CPUMap`, `bpf.DevMapHash`, `bpf.XSKMap`)

- Declare with `var C = bpf.CPUMap{MaxEntries: N}` etc.; the eBPF side uses the same terminal as DevMap, `return M.Redirect(ctx, k, fallback)` / `M.RedirectIf(ctx, cond, k, fallback, otherwise)` (only the last statement of an xdp body; fallback is a constant verdict). The return value is the requested action, not the delivery result
- **cpumap**: the key is the CPU number and the value is the queue size (`C.Set(cpu, qsize)`). For each Set CPU a kernel thread `cpumap/<cpu>/map:<id>` runs, and it stops when the map is closed. **MaxEntries must be at most the number of possible CPUs** — a larger declaration is stopped, named, by gobpf.Load (LoadCollectionSpec) before load (cilium v0.22 silently shrinks it). Creation needs CAP_BPF
- **devmap_hash**: the key is any u32 (not an index) and the value is the target ifindex (`D.Set(k, ifindex)` — looked up in the netns of the process that Sets). Creation needs CAP_NET_ADMIN
- **xskmap**: the key is the rx queue and the value is the fd of an AF_XDP socket (`X.Set(queue, fd)` — creating the socket and binding it to a device / queue are the user's responsibility; go has no AF_XDP library). Creation needs CAP_NET_ADMIN
- A redirect to a veth needs NAPI on the receiving veth (GRO or an XDP program on the receiving side)
- On real kernels: delivery to the 3 kinds of targets and the fallback with real packets on a veth in a test netns, and the creation and removal of cpumap's kernel threads, agree with the model on all three kernels as root

## perf_event (`bpf.PerfEventContext`, `gobpf.AttachPerfEvent`)

- `func f(ctx *bpf.PerfEventContext)` (no result, no directive) is a perf_event program. `ctx.SamplePeriod()` is the sample period (bpf_perf_event_data's sample_period — readable inside loops too). regs and addr cannot be read (not in bpf-mlir's capability table), and the arch is x86_64 only (offset 168 depends on the size of x86_64's pt_regs — the requirements' arch is checked before load)
- Attach with `gobpf.AttachPerfEvent(objs, fn, fd)` — fd is an event the user opened with perf_event_open (type, pid / cpu and sample_period are loader inputs). Unless pinned, the link detaches on Close or at process exit

With an exclude_kernel event, the program sees only samples with user-mode regs (samples with kernel regs are dropped before overflow)
- A non-root loader needs CAP_BPF + CAP_PERFMON and permission to open the event (with `kernel.perf_event_paranoid` 2, an exclude_kernel event on your own thread — 7.1.8)

## Stack traces and perf events (`bpf.StackTrace` / `bpf.PerfEventArray`)

- **fentry program bodies only** (`func f(ctx *bpf.FentryContext)` — other contexts are stopped by Go's types). They cannot be written in a loop body (GB018). The status is raw (int64), and **a statement discarding it is GB017** — if you do not count it, write `_ = …` explicitly
- `var Stacks = bpf.StackTrace{MaxEntries: N, Depth: D}` with `st := Stacks.KernelID(ctx, skip)` / `KernelIDReuse(ctx, skip)` (helper bpf_get_stackid — skip is a constant 0 to 255). Success is an id (≥ 0 — the IP list via `Stacks.Get(id)` on the user side); depth ≤ skip is −EFAULT (−14); a bucket collision is −EEXIST (−17); **reuse gives −ENOMEM (−12) when there is no free element** (it takes a new element before returning the old one — observed with MaxEntries 1). The same path gives the same id only with a MaxEntries free of collisions. **If you use non-reuse KernelID / UserID repeatedly, delete stacks you have read** (`Stacks.Delete(id)` after `Stacks.Get(id)` — the same for StackBuildID): another stack hitting the bucket of a stack left behind gives −EEXIST (in a test stacking the stacks of 4 fixtures into a 1024-bucket map under parallel load, 4 out of 400 times; 0 / 400 when deleting after reading). The same stack has the same id, so deleting it while an event with that id has not been read makes that Get ENOENT — delete in a form where the reader reads each id once. The reuse variants do not return −EEXIST and replace the old stack (an id read earlier may point at a different stack)
- **Bucket collision rule** (a model copied from kernel/bpf/stackmap.c of the three kernels agrees 30 times on each of the three kernels with reuse / non-reuse maps of MaxEntries 2): id = `jhash2(IP list, 0) & (number of buckets − 1)` (the number of buckets is MaxEntries rounded up to a power of two; there are MaxEntries elements). When a different stack is in the same bucket, the non-reuse form gives −EEXIST and **the previous stack stays**; reuse, if a free element exists, overwrites successfully and **returns the same id, and a Get by an event that received that id earlier reads the new stack** (a silent mix-up — observed on all three kernels). Without a free element, −ENOMEM. **If you read stack ids later, avoid reuse**, or use a MaxEntries large enough to avoid collisions (the IP list changes with each load and boot — whether it collides cannot be known in advance)
- **The first frame at skip 0 is the return address of that call inside the eBPF program** (a different address per call site), followed by the trampoline, the attached function and the caller — on all three kernels `bpf_prog_…_onTest1 < bpf_trampoline_… < bpf_fentry_test1 < bpf_prog_test_run_tracing < __sys_bpf < …`. Turning IPs into names is the user's job (/proc/kallsyms — non-root sees 0)
- **If another tracing program is attached to the same function, the addresses of the first frames of the stack can change**: the fentry / fexit trampoline is rebuilt at each attach / detach to the same function, and the addresses of the frames inside it (which appear at skip 0 and skip 1) change — the stack id changes even for the same call path, and so does the bucket (non-reuse KernelID −EEXIST and collisions in a small MaxEntries map also vary per run). Tests that compare stack ids or contents exactly should run where no other tracing program (parallel tests, other tools on the same host) attaches to the same function, or check that the differences are only frames in the image region (≥ 0xffffffffc0000000 on x86_64) and retry (the repository's tests use internal/tracetest.ImageOnlyDiff). Stacks from skip ≥ 2 (past the trampoline) do not change
- **`Depth ≤ kernel.perf_event_max_stack`** (a host sysctl — default 127): not checked at compile; `gobpf.Load` reads it before creating the map and stops, naming it (if it cannot be read, it adds the text to the map creation EINVAL)
- `var Events = bpf.PerfEventArray[Ev]{}` (MaxEntries cannot be written — 0; the loader sets it to the number of possible CPUs) with `st := Events.Output(ctx, Ev{…})` (helper bpf_perf_event_output, the current CPU): 0 is success, **−ENOENT (−2) means the current CPU's slot has no reader**, and −ENOSPC (−28) is a ring overflow
- The user side: `rd, _ := gobpf.NewPerfReader(&Events, pagesPerCPU)` **before attach** (rings on all CPUs and map registration — `gobpf.AttachFentry` stops, naming it, a program that outputs to a map without an open reader). `rd.Read()` gives `PerfRecord{Value, CPU, Lost}` (Lost > 0 is an overflow notice without a Value). **`rd.Lost()` agrees with the count of −ENOSPC on the eBPF side only after the overflowed ring has been read through and the next successful output from the same CPU has been read** (the kernel writes the overflow notice at the next successful write). Ordering is per CPU only
- **User stacks**: `Stacks.UserID(ctx, skip)` / `UserIDReuse` (uprobe, kprobe, fentry bodies — ctx is a `bpf.StackContext`) and a build-id stack map `var Builds = bpf.StackBuildID{MaxEntries: N, Depth: D}` with `Builds.UserID(ctx, skip)`. The user side uses `Stacks.Get(id)` (the IP list — the depth is `bpf.StackDepth`) and `Builds.Get(id)` (`[]bpf.StackFrame` — each element's `Status` is `bpf.StackFrameValid` (build id and file offset) or `bpf.StackFrameIP` (no build id, an IP). Do not discard the status)
- **User stacks are walked by frame pointers only** (x86_64): for a target without frame pointers (the default of gcc / clang -O2 / -O1), the success stays id ≥ 0, but after #0 (the probed location) the stack **ends at depth 1 (greetwatch's greeter) or becomes fake frames from following an rbp the caller uses for general purposes** (addresses outside executable mappings — **they can also appear as status 1** in a build-id stack). The symptom is "depth 1, or frames outside r-x" — if you need the caller list, build the target with `-fno-omit-frame-pointer`. If the uprobe is at a function entry (`push %rbp` or endbr64), the kernel adds the return address at [sp] as #1
- **Frames of a binary linked by Go's internal linker have build-id status 2**: the `.note.gnu.build-id` section exists but is outside the PT_NOTE segment, and the kernel looks only at PT_NOTE (an externally linked cgo binary has it inside PT_NOTE). **A non-cgo Go binary linked with `-ldflags=-linkmode=external` also gets `.note.gnu.build-id` inside PT_NOTE, and all 6 frames of the user stack have valid build ids** (measured by bpf-mlir — the internal linker stays as IPs). Build Go targets that need build-id stacks with external linking. User stacks from uprobes need CAP_SYS_ADMIN, and user stacks from kprobe / fentry need CAP_BPF + CAP_PERFMON
- **Why use perf events when RingBuf exists**: BPF_MAP_TYPE_RINGBUF is from 5.8 — compatibility with older kernels and with existing tools that read perf rings, and per-CPU rings (reservations do not compete with other CPUs). The three kernels this repository targets all have RingBuf, so for new code RingBuf is the default (it also keeps a global order)

## Spin locks and timers (`bpf.SpinLock` / `bpf.Timer`)

- They are record field types. **A record has one lock or one timer (not both), and that record can only be a `bpf.Array` value** (Hash, PerCPU, RingBuf, PerfEventArray and keys are GB026). The field cannot be read or written as a value (GB016), and a literal of that record (Update / Output) cannot be written. The ops are **xdp programs only** (what bpf-mlir's compiler supports — other kinds are GB026). **kprobe / uprobe programs cannot use maps of lock / timer records** (the kernel rejects them — GB026; fentry can)
- Lock: `bpf.WithLock(&p.Lock, func() { p.A++; p.B++ })` — a closed critical region (ebpf.spin.region). Inside the func, **only reads and writes of fields of the same p other than the lock, integer arithmetic, and local variables declared inside**: calls (KtimeNs too), if / for, return, assignment to outer variables and other pointers are GB026; break is Go's type check; goto / defer / panic is the capability check (GB011). The user side's `Array.Get` / `Put` on a map of lock records **always use BPF_F_LOCK** — a read without it reads the middle of a region (in a control run without it, 72 to 2252 mixed reads on the three kernels)
- Timer: `if st := p.T.Init(); st == 0 { _ = p.T.SetCallback(onFire); _ = p.T.Start(ns) }` — Init's map is the map of the Lookup that returned p, the clock is monotonic, and all statuses are raw (a statement discarding one is GB017). **A second or later Init is −EBUSY (−16) — SetCallback / Start only inside the then of an if whose Init status is 0** (`if p.T.Init() == 0`; checking an earlier `st := …` in a later `if st == 0` is also allowed — reassigning st is not). Starting every time without checking restarts it again after it fires (observed in a mutation run — Fired 2). One Start is one firing
- Callback: `func onFire(v *R)` (R is the timer record) — a function written directly in SetCallback. The body may only read and write fields of v other than the timer, do integer arithmetic, `bpf.KtimeNs()`, **if (with else and nesting — the bodies follow the same rules)**, and **`st := v.T.Start(ns)` on its own timer** (GB026 — Init / SetCallback, for, other calls, maps and pointers outside v are stopped; a statement discarding Start's status is GB017). One callback uses one map
- **Periodic timers** (bpf-mlir's timer.start in callbacks and ebpf.if): restarting its own timer up to a limit in the callback with `if c < N { st := v.T.Start(P); … }` stops after N times (the restart status is 0). A restart without a limit stops at the last uref of the map (closing Load's objects) — **keep the objects open on the user side until the end of checking**. On real kernels: a timer with N = 5 and D = P = 20 ms, started by one xdp test run, stops after 5 times on all three kernels as root (6.12 / 6.6 in bpf-mlir's test VM kernels) (the restart status is 0), the first firing is at least D, the interval is at least P, and the ID disappears after closing. On 7.1.8 non-root, the same with CAP_BPF + CAP_NET_ADMIN (xdp — CAP_SYS_ADMIN also works)
- **A user-side `Put` on a map of timer records is GB026** — the kernel stops a running timer on a userspace update (it does not fire on the three kernels). The kernel creates array entries with 0, so no initialization is needed. Get can read (Timer and SpinLock fields are always 0)

## Large ring buffer events and the reservation limit

- **Large events can be written with Output — they do not go through the 512-byte stack**: the frontend lays out every byte of the record, filling fields and array elements omitted in the literal with 0, and bpf-mlir's store_record stores a record that covers every byte directly into the reservation without building it on the stack. A 65520-byte event runs with an 8-byte stack on all three kernels
- **The cost is a number of instructions proportional to the size**: a program with a 65520-byte event is about 16400 instructions (including stores of 0), and about 550 at 4080 bytes. Several large Outputs in one program add up
- **Events up to about 250 KB can be compiled**: when the instruction estimate of the reservation's content exceeds a threshold (23552), the compiler outlines the content into a static function `__ebpf_present_<function>_<n>` (one more FUNC in the ELF's BTF — ELFs below the threshold are byte-identical; in this repository the 65520-byte event of rbsize is above the threshold). On real kernels: every byte of a 131056-byte event (ring 131072) agrees with the model on all three kernels as root and in the non-root table (differential rbbig), and a 204800-byte event (ring 262144) also passed on all three kernels (68657 verifier instructions — not included in the differential package because the generated .mlir is large). The frontend lays out every byte of the literal in the .mlir — the generated .mlir of a large event is large (about 3 MB for 131056 bytes). **Names starting with `__ebpf_` are reserved** — using one for an eBPF-side function name (program, subprogram, timer callback) is GB013 (bpf-mlir stops only when it collides with an outline name — the frontend stops on the prefix). **The remaining limit**: a form where a single branch arm inside a reservation exceeds BPF's 16-bit jump offset (32767 instructions) is stopped by ebpf-compile at the Output line with `… longer than a BPF jump can reach (32767 instructions)` (inside an Output reservation there is one arm — large events have this form). This hits before the verifier's limit of 1M instructions
- **The limit is the ring size**: the size S of an event V must satisfy `round_up(S + 8, 8) <= MaxEntries - 1`, that is **S ≤ MaxEntries − 16** (the kernel's reservation adds an 8-byte header and rounds to 8, and cannot take a record that exactly fills the ring — the two checks of `__bpf_ringbuf_reserve`, the same on all three kernels). A larger declaration is **GB009** at the MaxEntries position (MaxEntries appears in the message). A boundary event fits only one in the ring, and the next Output is false until the reader reads. **In a non-empty ring, Output can be false even for a size that fits** — count with Output's result or CountDropsIn
- **What does not exist**: a general form that reserves and then writes field by field, or discards after looking at the content — bpf-mlir accepts conditional submit / discard, and go uses it through `RingBuf.Reserve` (the "Ring buffer reservation" section) and through `OutputStrOrDiscard`, which discards on a read_str failure. Bytes of a reservation that are not written keep the remains of an earlier event (the kernel does not zero reservations), so a reservation must write every byte it needs. Otherwise, decide local variables conditionally and write them in the Output literal

## Known limitations (those that affect users)

**The list of what is outside the scope, unmeasured paths within groups, the limits below and non-root gaps, sorted by kind (fixable / bpf-mlir / kernel / unmeasured / no demand), is [limits.md](limits.md)**. Unmeasured paths within groups are in "Unmeasured paths and notes within groups" of [scope.md](scope.md), per group. Here are the limits that belong to no group (tools, ways of writing, tests):

- **Getting ebpf-compile**: outside this repository, point `EBPF_COMPILE` at ebpf-compile (gobpf only looks in `build/bpf-mlir/bin` under the module root). See the tutorial for installing
- **One generated object per binary** (a second Register panics) — put the eBPF-side programs in one package
- **Writing constraints**: `ctx.Check` only has the form `if w, ok := ctx.Check(off, n); ok { … }` (`_, ok :=` and an `ok && …` condition are GB005) — even when you only want to check the length, name the window and use it (for example `_ = w.U8(127)` in xdpwindow)
- **stack id reuse**: `KernelIDReuse` / `UserIDReuse` silently replace the previous stack on a bucket collision and return the same id — if you read the id later, use the non-reuse form (and Delete after reading) ("Bucket collision rule" in the stack trace section)
- **Compiler suffixes on kprobes**: a function present in kallsyms only with a suffix such as `.part.0` can be written by its suffixed name only for a program that **does not read arguments** — the count can differ from the number of calls of the source function (the kprobe section)
- **Non-root kallsyms**: kernel stack IPs cannot be turned into names unless root (addresses appear as 0)
- **Assumptions of user-stack reads**: the caller list is correct only when the target has frame pointers (otherwise depth 1 or fake frames — build-id status 1 is not necessarily genuine), and frames of a binary linked by Go's internal linker cannot get a build id (status 2). Details in the "Stack traces and perf events" section
- **LoadUnchecked** skips the checks of kernel capabilities (including fexit's retsig, uprobe's calling convention, and CO-RE kfield / farg / arg_nullable) — the default is Load
- **Up to two borrows at a time**: a second Lookup inside the checked arm of a Lookup is accepted if it is on **a different map**, or on **a different constant key of the same map** (`M.Lookup(1)` inside `M.Lookup(0)`) — reads and writes, `bpf.AtomicAdd` and nested record paths on both borrows (the outer borrow can be used in the inner absent arm too). A second one that may point at the same value (a variable key of the same map, the same constant key, or a map of the same value type as a subprogram's borrowed argument) is **GB029 BorrowAlias** — copy the value to a local before the second Lookup. A third is GB001. Rules that do not change: a borrow outside a loop cannot be carried into the loop (GB018), only one is passed to a subprogram (GB013), a WithLock region is only the lock record (GB026), and nesting the nil check of a subprogram's unchecked argument is GB001. GB028's origin is tracked per borrow (`q.S = q.S + p.X` is stopped, `q.S = p.X + 1` is accepted)
- **Checked pointers cannot be used inside loops** (GB018): `if p := M.Lookup(k); p != nil { for … { p.F … } }` — reads and checks of kernel pointers are outside the loop; to walk an array of nested records with a loop, Lookup inside the loop
- **Writing tests**: do not compare the run count of a test run with repeat > 1 as an exact number (cilium v0.22 restarts the whole run on EINTR with repeat > 1 — use `internal/testrun.Count`). A test that compares tracing counts exactly should check whether the trigger is a shared resource (bpf_fentry_test1 is called by every tracing test run in the system) and filter the program on the test's tgid / tid

## tp_btf and CO-RE (`//gobpf:tp_btf`, `bpf.TPArg[T]`, `bpf.TPArgInt[T]`, `bpf.FentryArg[T]`, `bpf.FentryArgInt[T]`)

- **fentry integer arguments** (bpf-mlir v1.11.0): `x := bpf.FentryArgInt[T](ctx, i)` — the same form as TPArgInt (only a top-level statement in an fentry body; i is a constant 0..11; earlier arguments that are not read need no declaration; may be mixed in the same program with FentryArg structs — one declaration per argument). T has the same width and sign as the target argument — **the kernel's char is unsigned (uint8)**, size_t is uint64. A mismatch (for example char as int8) is stopped, named, by gobpf.Load's check (farg against the target BTF's func_param). Measured on all three kernels with the test-run values of bpf_fentry_test1 to 6 and with tcp_sendmsg's size (the Delete trigger of the sk differential test of local storage)

- Kernel structs are declared with local Go types: `type Task struct { _ bpf.Kernel \`kernel:"task_struct"\`; Pid int32 \`kernel:"pid"\`; … }` — only the fields you read. Fields are **int8 to int64 / uint8 to uint64** (kfield.load — the width and sign must match the target kernel's type), **`[N]byte` / `[N]int8` (1 ≤ N ≤ 64)** (char arrays — copy only), and **`*U`** (U also a local kernel type — following). Offsets have nothing to do with the Go layout (CO-RE — decided at load time from the target BTF)
- Arguments: `p := bpf.TPArg[T](ctx, i)` and `x := bpf.TPArgInt[T](ctx, i)` (integer arguments — sched_switch's preempt etc.) are top-level only. **Arguments you do not read need no declaration** (null in the schema). An argument that may be NULL is `if p := bpf.TPArg[T](ctx, i); p != nil { … } [else { … }]` (nullable in the schema — kptr.check). A struct pointer argument of fentry is only `if p := bpf.FentryArg[T](ctx, i); p != nil { … }` (it may always be NULL — checked before load against the type of the target function's argument by the farg rows of the requirements)
- Kernel pointers are **read-only** (`p.F` — each read is one CO-RE load). Writes, `&p.F`, `*p`, reassignment and passing are GB027 / GB011. A `*U` field is only `if m := p.F; m != nil { … m.G … } [else { … }]` (kfield.ptr — it may always be NULL; `p.F.G` outside the check is GB005). A `[N]byte` field only as `q.F = p.G` into a field of the same type of a checked record pointer (kfield.copy — reading an element `p.G[i]` is GB027). Reads and checks inside a loop are GB018
- **On the 6.6 kernel, a tp_btf program that reads a struct (pointer) argument cannot be loaded** — the 6.6 verifier does not mark arguments that may be NULL, and a NULL read silently becomes 0, so gobpf.Load's check (arg_nullable — message `reads pointer argument <i>`) stops it, naming it. **A tp_btf that reads only integer arguments (`bpf.TPArgInt`) or reads no arguments can be loaded on 6.6 too** (bpf-mlir v1.1.0's verdict version 6 — measured on all three kernels). A non-root loader stops with arg_nullable_mark_unknown if it cannot probe the NULL mark
  - A program with an argument that may be NULL in the checked form (`if p := bpf.TPArg[T](ctx, i); p != nil`) is likewise stopped by the gate on 6.6 (the 6.6 verifier removes the NULL branch)
  - Note (from reading bpf-mlir's source analysis, 2026-09-27): reading an argument that may be NULL without a check on 6.6 is expected to be a kernel NULL dereference rather than "silently 0", because a trusted pointer load is not PROBE_MEM (not confirmed at run time — bpf-mlir decided not to build a program that triggers it on purpose). The stopping verdict (arg_nullable) is the same.
- **Field spelling, width and sign are stopped, named, by gobpf.Load's check (kfield)**. **LoadUnchecked does not check** — cilium's CO-RE silently turns a missing field into an invalid instruction (not an error) and does not look at width or sign

## Nested records (struct fields, `[N]Inner`, `[N][M]uintK`)

- Accepted forms: a record field of a named struct of the same package (which itself satisfies the record rules), a one-dimensional array of it, and a two-dimensional array of integers. Paths are `p.A.B`, `p.Arr[2].F`, `p.M[1][2]`, which become bpf-mlir paths (`a.b`, `arr[2].f`, `m[1][2]`). An inner struct has its own record entry in the schema (the Go type name)
- **The limits are GB016** (the same as bpf-mlir's RecordPath): nesting depth up to 3 (path components ≤ 3), array dimensions up to 2, record arrays one-dimensional only, no anonymous structs, and **a record with a lock / timer cannot be nested in another record** (put the lock / timer in the outer record)
- **A whole nested record is not a value** (GB016): `x := p.A`, `p.A = p.B`, `p.Pts[1] = p.Pts[0]` are stopped — read and write each leaf (`p.A.X`). Nested literals inside a map Update / ring buffer event literal (`Rec{S: Seg{A: Pt{X: 1}}}`) are accepted, and omitted leaves are 0
- **Variable indexes**: an array of integer elements uses the usual range check (`if i < uint32(len(p.A.Arr)) { … p.A.Arr[i] … }`). For an array whose elements are records or arrays, use `p.Pts[i].F`, `p.M[j][k]` inside the then arm of a check of the same form (rows and columns with nested checks) — the same index in the else arm is GB006 (the proof is only for the then arm). Generation emits a `ref.index` per read and write, and its out_of_range arm (unreachable — a read gives 0) is named in a comment. Assigning to the index inside the check is GB014
- **AtomicAdd** accepts a nested leaf (`&p.Cnt.Hits`) — alignment is checked against the absolute offset from the start of the record. A path with a variable index is GB021
- User side: the generated Decode reads nesting down to the leaves. The pre-load check (bindrt's Records) names differences in the order and widths of inner records with `record:<name>`

## Non-atomic read-modify-write of shared maps (GB028)

- Reading a shared (not per-CPU) map value and writing back to the same value is **Rejected** (GB028 NonAtomicRMW — it loses counts on multiple CPUs, and the verifier accepts it): `op=` and `++` / `--` on the path of a borrow `p := M.Lookup(k)`, `=` that reads the same path (or a parent / child path) back directly or through a local (`x := p.N; p.N = x + 1` — also through locals, if-merges and values across loops), and `M.Update(k2, e)` carrying a value of the same map
- **Origins across subprograms are tracked too**: a callee's return value carrying a map value (`p.N = readN() + 1`, `C.Update(0, readC() + 1)`) and a callee writing an argument value into the map (the caller reads R[0].N and calls `writeN(x + 1)`, and writeN writes R[0].N) are GB028 even through callees of callees (an AtomicAdd delta is GB021) — at the call position, with a message naming the callee's write form and the read path
- **Accepted only when the keys can be shown to differ** (different constants — fail closed): `if p := C.Lookup(0); p != nil { C.Update(1, *p) }` is accepted, and `C.Update(k, *p + 1)` (k a variable — ranges may overlap) is stopped
- `M.AtomicAdd(k2, d)` / `AddOrInit` on an integer map whose d is a value of the same map (with a key not shown to differ) is **GB021** (the same meaning as the rule for the delta of a record's `bpf.AtomicAdd`)
- Accepted: per-CPU maps (no CPU writes the same slot at the same time), paths of **that record** inside a `bpf.WithLock(&p.Lock, …)` region, other maps, and stores to another field of the same record (`p.A = p.N * 3`)
- An RMW on its own value in a timer callback (`func onFire(w *Win) { w.Fired++ }`) is accepted — one map value has one bpf_timer (the kernel's btf.c rejects a second with E2BIG — all three kernels), and one hrtimer's callback does not run concurrently with itself. **If the program side writes the same field of the same map, both are GB028** (the callback and the program can run concurrently on different CPUs)
- Fixes: for additions, `bpf.AtomicAdd(&p.N, d)` / `M.AtomicAdd(k, d)`; to count per CPU, `bpf.PerCPUArray` / `PerCPUHash` (sum with GetPerCPU on the user side); for updating a group, xdp's `bpf.WithLock`; for copies, another map or a different constant key
